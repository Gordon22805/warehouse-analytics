# Power BI: сборка отчёта

Инструкция для сборки интерактивного отчёта на готовых витринах из `data/powerbi/`.
Файл `.pbix` в репозиторий не входит: он бинарный, весит десятки мегабайт и
не даёт осмысленного diff. Вместо него здесь описан воспроизводимый путь
сборки и готовый набор мер.

---

## 1. Что лежит в `data/powerbi/`

Модель построена по схеме «звезда»: отдельно атрибуты, отдельно факты.

| Файл | Тип | Строк | Назначение |
|---|---|---|---|
| `fact_orders.csv` | факт | 13 331 | доставленные заказы, одна строка = один заказ |
| `fact_warehouse_load.csv` | факт | 1 103 | загрузка складов по дням |
| `dim_warehouse.csv` | измерение | 6 | склады |
| `dim_delivery_method.csv` | измерение | 5 | тарифы доставки |
| `dim_region.csv` | измерение | 10 | регионы |
| `dim_date.csv` | измерение | 184 | календарь без пропусков |
| `agg_daily.csv` | агрегат | 184 | сводка по дням |
| `agg_warehouse_summary.csv` | агрегат | 6 | сводка по складам |
| `agg_method_summary.csv` | агрегат | 5 | сводка по тарифам |
| `agg_region_summary.csv` | агрегат | 10 | сводка по регионам |
| `agg_sla_grid.csv` | агрегат | 30 | склад × тариф |
| `hypothesis_tests.csv` | результат | 6 | проверка гипотез |

Агрегаты (`agg_*`) — это уже посчитанные сводки для карточек и таблиц.
Не соединяйте их с фактом: при срезе по другому измерению суммы задублируются.
Для интерактивных срезов используйте факт плюс измерения, агрегаты — только
для статичных карточек и текстовых панелей.

## 2. Загрузка данных

1. Откройте Power BI Desktop → **Получить данные** → **Текстовый или CSV-файл**.
2. Загрузите по очереди: `fact_orders`, `fact_warehouse_load`, `dim_warehouse`,
   `dim_delivery_method`, `dim_region`, `dim_date`, `agg_daily`.
3. В окне предпросмотра нажмите **Преобразовать данные** и проверьте типы:
   - `order_date` в `fact_orders` → **Дата** (не «Дата и время»);
   - `date` в `dim_date` → **Дата**;
   - `load_date` в `fact_warehouse_load` → **Дата**;
   - `order_created_at`, `shipped_at`, `delivered_at` → **Дата и время**;
   - `is_delayed`, `is_next_day_ship`, `is_evening_order` → **True/False**;
   - `order_hour`, `dispatch_lag_days`, `items_count` → **Целое число**;
   - `total_amount`, `goods_amount`, `delivery_fee`, `revenue` → **Десятичное число**.
4. **Закрыть и применить**.

Кодировка файлов — UTF-8 с BOM, поэтому кириллица читается без настройки.

---

## 3. Связи между таблицами

Перейдите на вкладку **Модель**. Создайте связи, все с кардинальностью
**«один ко многим»** и направлением фильтра **от измерения к факту**:

| Из (измерение) | В (факт) | Активна |
|---|---|---|
| `dim_warehouse[warehouse_id]` | `fact_orders[warehouse_id]` | да |
| `dim_warehouse[warehouse_id]` | `fact_warehouse_load[warehouse_id]` | да |
| `dim_delivery_method[method_id]` | `fact_orders[method_id]` | да |
| `dim_region[region_id]` | `fact_orders[region_id]` | да |
| `dim_date[date]` | `fact_orders[order_date]` | да |
| `dim_date[date]` | `fact_warehouse_load[load_date]` | да |

Две связи `dim_date` к разным таблицам не конфликтуют, потому что ведут
к разным фактам.

После создания связей:

- щёлкните `dim_date` правой кнопкой → **Пометить как таблицу дат** → `date`;
- в `dim_date` задайте сортировку: `month_name` сортировать по `month_number`,
  `weekday_name` — по `weekday_number`. Иначе месяцы выстроятся по алфавиту.

## 4. Меры

Откройте `powerbi/dax_measures.dax`, скопируйте меры в модель
(**Создать меру** для каждой). В файле двадцать пять мер, сгруппированных по смыслу.

Ключевые для защиты проекта:

| Мера | Что показывает | Ожидаемое значение |
|---|---|---|
| `Delivered Orders` | объём доставленных заказов | 13 331 |
| `Revenue` | выручка | 544 879 371 |
| `Average Order Value` | средний чек | ≈ 40 873 |
| `Delay Rate` | доля задержек | 14,23 % |
| `Delay Rate Same Day Ship` | задержки при отгрузке в день заказа | 5,32 % |
| `Delay Rate Next Day Ship` | задержки при отгрузке на следующий день | 25,91 % |
| `Dispatch Risk Ratio` | во сколько раз растёт риск | 4,87 |
| `Next Day Ship Share` | доля заказов с пропуском рейса | ≈ 43 % |
| `Avg Picking Minutes` | среднее время сборки | 48,7 мин |
| `Avg Utilization` | средняя загрузка складов | — |
| `Overloaded Days Share` | доля дней перегрузки | — |

Если `Delay Rate` не равна 14,23 % — почти всегда причина в типах данных
(`is_delayed` загружен как текст) или в лишней связи, размножающей строки.

## 5. Структура отчёта

Четыре страницы. Первая отвечает на главный вопрос, остальные её раскрывают.

### Страница 1. Обзор

- Карточки: `Delivered Orders`, `Revenue`, `Average Order Value`, `Delay Rate`.
- Линия: `Revenue` по `dim_date[year_month]`.
- Столбцы: `Delay Rate` по `dim_warehouse[warehouse_name]`.
- Срез: `dim_date[year_month]`, `dim_warehouse[warehouse_name]`,
  `dim_delivery_method[method_name]`.

### Страница 2. Причины задержек

Главная страница проекта.

- Столбцы: `Delay Rate` в разрезе `fact_orders[is_next_day_ship]`
  — два столбца, 5,32 % против 25,91 %.
- Карточка: `Dispatch Risk Ratio` — 4,87.
- Столбцы: `Delay Rate` по `dim_warehouse[warehouse_name]`.
- Точечная диаграмма: `Avg Utilization` по X, `Delay Rate` по Y,
  точки — склады. Видно, что перегрузка и задержки связаны.

### Страница 3. Склады и время

- Столбцы: `Avg Picking Minutes`, `Avg Packing Minutes` по складам.
- Линия: `Avg Utilization` по `dim_date[date]`, порог 100 % — линией.
- Карточки: `Overloaded Days`, `Overloaded Days Share`.
- Таблица: склад, заказы, выручка, `Delay Rate`, `Picking vs Network`.

### Страница 4. Доставка и регионы

- Матрица: `dim_delivery_method` по строкам, меры `Avg Transit Days`,
  `Delay Rate`, `Avg Delay Days`.
- Столбцы: `Delay Rate` по `dim_region[region_name]`, сортировка по убыванию.
- Карточки: `Avg Delivery Days`, `Severe Delay Rate`.

## 6. Оформление

- Тема: **Вид → Темы** → выбрать светлую, залить фон `#FFFFFF`.
- Цвета: хорошее `#17A398`, предупреждение `#F4A259`, плохое `#C1352B` —
  те же, что на графиках matplotlib, чтобы отчёт и PNG выглядели как одно целое.
- Формат чисел: `Revenue` — целое с разделителем разрядов и суффиксом «₽»;
  доли — один знак после запятой с «%».
- Условное форматирование `Delay Rate`: заливка по правилам, порог 15 %.

## 7. Сохранение и публикация

1. **Файл → Сохранить как** → `powerbi/warehouse_analytics.pbix`.
2. Для портфолио: **Опубликовать** → «Моя рабочая область» → получить ссылку.
   Публикация требует рабочей или учебной учётной записи; личная почта не подойдёт.
3. Альтернатива без публикации — экспорт страниц в PNG или PDF
   и добавление их в README.

---

## 8. Проверка, что отчёт собран верно

Сверьте значения в карточках с таблицей из раздела 4. Если расходятся:

| Симптом | Причина |
|---|---|
| `Delay Rate` = 100 % или 0 % | `is_delayed` распознан как текст |
| Заказов больше 13 331 | лишняя связь размножает строки |
| Выручка завышена кратно | соединены факт и агрегат `agg_*` |
| Месяцы по алфавиту | не задана сортировка `month_name` по `month_number` |
| `DATEADD` даёт пусто | `dim_date` не помечена как таблица дат |
| Кириллица «кракозябрами» | файл открыт не как UTF-8 |
